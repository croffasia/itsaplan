# Languages

The interface language is an account preference. A cookie gives it to the server render, and
next-intl reads that cookie one time for each request.

## The message files

`apps/web/messages/<locale>/<namespace>.json`. There is one file for each top-level namespace,
and the same set of files for each language. A namespace is a domain (`issue`, `members`,
`settings`), not a page. Thus a screen that contains parts of more than one feature reads more
than one namespace.

English is the source language. `src/i18n/messages.ts` imports all the English files statically.
The messages of the selected language then replace the English text, key by key. A key with no
translation keeps its English text and does not show the key path.

TypeScript uses the same imports for the type `Messages` in `global.d.ts`. That type gives the
permitted keys for `t('…')`. `loadMessages` imports the other languages dynamically, one
namespace at a time.

## Where the code is

| File                                           | Content                                                    |
| ---------------------------------------------- | ---------------------------------------------------------- |
| `apps/web/messages/<locale>/*.json`            | the messages, one file for each namespace                  |
| `apps/web/src/i18n/messages.ts`                | the English imports, `loadMessages`, the English fallback  |
| `apps/web/src/i18n/request.ts`                 | reads the cookie and gives the messages to next-intl       |
| `apps/web/src/i18n/locales.ts`                 | the language list, the labels, the flags, `isLocale`       |
| `apps/web/src/i18n/cookie.ts`                  | writes `NEXT_LOCALE`                                       |
| `apps/web/global.d.ts`                         | types each key against the English files                   |
| `apps/web/src/components/preferences-sync.tsx` | writes the cookie from the account preference, and refreshes |
| `apps/web/src/components/locale-toggle.tsx`    | the language switcher                                      |
| `apps/web/src/hooks/useDateFnsLocale.ts`       | the month names and the weekday names of the calendar      |
| `apps/api/src/user-preferences/`               | the stored preference and its validation                   |

## How to add a key

Add the key to `messages/en/<namespace>.json` first. Then add it to the other languages. The
English file gives the type. Thus a `t('…')` for a key that is not in that file causes a
typecheck error. A key that is absent from a translated file causes no error.

## How to add a namespace

Make the file in each language directory. Then add the namespace to `defaultMessages` in
`src/i18n/messages.ts`. No code finds the file automatically.

## How to add a language

There are four locations, and no migration is necessary.

1. Copy `messages/en/` to `apps/web/messages/<code>/` and translate the files. A partial
   translation is permitted, because the other keys show in English.
2. Add the code to `LOCALES` in `apps/web/src/i18n/locales.ts`. Add the name of the language, in
   that language, to `LOCALE_LABELS`. Add a flag to `LOCALE_FLAGS`. TypeScript types both
   records by locale, thus an absent entry causes a typecheck error.
3. Add the applicable import from `date-fns/locale` to
   `apps/web/src/hooks/useDateFnsLocale.ts`. If you do not, the month names and the weekday
   names of the calendar stay in English, and no error occurs.
4. Add the code to `LOCALES` in `apps/api/src/user-preferences/store.ts`, and to `Locale` in
   `routes.ts`. If you do not, the API refuses the new code with status 422, and the switcher
   cannot save it.

The `user_preference.locale` column is a plain `text` column with no CHECK, so the set of
languages can increase with no change to the schema.

## Dates and relative times

next-intl formats the dates, the numbers, and the relative times for the active locale.
`request.ts` also sets `now` one time for each request. The server render and the client use
that same value. Thus "3 hours ago" does not come from two different clocks, and the markup
agrees at hydration.

The calendar makes its own month names and weekday names with date-fns. `useDateFnsLocale` gives
the applicable date-fns locale. For a locale that is not in its map, it gives `enUS`.

## Rejected alternatives

**One file for each namespace.** The alternative is one file for each language, with all the
namespaces in it. In that file each change conflicts with the other changes, and you must scroll
to find a key.

**All the messages go to the client.** `NextIntlClientProvider` receives the full set. If you
send only some namespaces with `pick()`, you save approximately 100 KB of raw JSON for each
page. But a namespace that is absent from that list then causes a failure at runtime, in the
component that needs it, and not at typecheck. The next-intl maintainer does not recommend this
at this size.
